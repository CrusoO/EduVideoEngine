# Engine workflow

How work on the engine is organised. Every agent session reads this file first. Paths are relative to the engine repository root. The engine repository is separate from YourTutor: all commands run in the engine repository, and YourTutor is never edited from an engine session.

**Do not commit (generated or local, listed in `.gitignore`):** `.stryker-tmp/`, `reports/`, `logs/`, `ledger/`, `node_modules/`, `.env`, build output, Python caches. A mutation result worth keeping goes into an ADR or a gate report as a table, not as a raw report file.

## 2. Which source wins when two disagree

1. The newest accepted ADR on that point. An ADR is accepted when it records a decision the owner stated or approved. A proposal overrides nothing.
2. `docs/change-orders/AM-1-to-21.md` and any later amendment file.
3. `docs/change-orders/CO-2.md`.
4. `docs/PEDAGOGY.md`, `README.md`, `docs/ENGINE_PLAN.md`.
5. `docs/ENGINE_ARCHITECTURE.md`.

If two sources at the same level disagree, or a rule is needed that none of them defines, stop and ask the owner. Do not guess. Record the answer as an ADR.

## 4. Prompt rules

1. Every model call is built from the frozen system prompt, a pass prompt (task, rules, error objects, one example) and data built in code (allowed values, input, output schema).
2. Once a prompt file has been used for a recorded call it is never edited. A change is a new version file; `prompts/VERSIONS.md` records its sha256 in the same commit.
3. `system.v1.md` and `planner.v2.md` are frozen. Do not create a system prompt v2.
4. The fixture key is prompt version, system prompt hash, model id and input. Changing the input data, even by adding a record kind, changes the key; that is why the planner hides CO-2 record kinds and patterns from v2 and v3 (ADR 0039).
5. Pedagogy rules go in the pass prompts (their rules block), never in the system prompt.
6. A prompt names no model, holds no key, no personal data and no copied text.
7. Re-record only fixtures whose prompt or input changed, in record mode, within the request caps. CI replays only.
8. After any prompt change, run `pnpm llm:sizes` and note the result in `prompts/VERSIONS.md`: each request must fit the provider's per-minute token limit.

## 5. Working rules for every session

1. Start by reading, in order: this file, `docs/ENGINE_PLAN.md`, `docs/ENGINE_ARCHITECTURE.md`, then what the task names.
2. Work on the branch the task names (section 7). One commit per work package, small commits inside it, clear messages.
3. Docs change in the same commit as the code they describe. Update `docs/ENGINE_PLAN.md` (state column and section 1) at every stop.
4. No live model calls unless the task says so; then only in record mode, within the verified request caps, and only with content the owner wrote or that is openly licensed. No student or personal data in any prompt.
5. No paid service. If something would need money, write an ADR with options and stop.
6. Never print, log, echo or commit a key or its length; report only "key present: yes or no". Run `pnpm secrets:check` before committing. If a key ever appears in output, stop and tell the owner to rotate it.
7. Do not bypass a network filter. Do not route around a security control.
8. Never guess a model id, a rate limit, a licence or an error cause: read the provider's page, call its list-models endpoint, or ask.
9. Every new rule gets a rejecting test, and every new gate gets a corrupted lesson it must reject. A gate without a failing corruption does not count as built.
10. Mutation floor: 90 per file in one full run, for every file in the main configuration. A waiver is an ADR with an expiry date and a survivor list, and a test that fails after the date.
11. Do not edit a frozen file: `prompts/system.v1.md`, `prompts/planner.v2.md`, the change-order files, an accepted ADR, an accepted gate report, the reference recordings.
12. Do not change what the architecture lists as not to be changed (section 15 of `docs/ENGINE_ARCHITECTURE.md`) without an ADR and the owner's approval.
13. Never reduce a result to a bare status code: log the sanitised error body.
14. When a task is ambiguous, pick the option that best fits the rules above and say so; when two sources conflict, section 2 decides; when neither decides, stop and ask.

## 6. Definition of done for a work package

- The gate in `docs/ENGINE_PLAN.md` for that package passes.
- `pnpm test` and the Python verifier tests pass; `tsc` is clean; `pnpm secrets:check` passes.
- New code is in the mutation scope and meets the floor, or is covered by a dated waiver ADR.
- ADRs written for every decision and deviation; `docs/ENGINE_ARCHITECTURE.md`, `docs/PEDAGOGY.md` and `README.md` updated if behaviour changed.
- The stop report below is written and the agent has stopped.

**Every stop report shows:** what was built and the commits; test, type-check and secrets results; mutation per-file table; ADRs added or changed; anything not done and why; any rule that could not be enforced deterministically; the decisions the owner must make.

## 7. Stages and stops

Task prompts are sent by the owner, one at a time, and are not stored in the repo. After each stop the owner brings the report to the reviewer before the next prompt is sent.

| Stage | Branch | Agent does | Stops with |
| --- | --- | --- | --- |
| C0 and WP2b with H1 to H4 | `co-2` | Conformance report against CO-2 and the amendments, then synthetic fixture, gates G1 to G7, 28 corruptions, hardening | Conformance report, `verify:gate` and `--list` output, mutation tables, variety-rule result per arc |
| A providers | `providers` | Smoke, diagnosis, probes 1 to 8 on prompt v1, planner on the v2 request, size check, decision gate | Probe table, planner comparison, size check, the decision |
| WP3 | `co-2` | Retrofit the reference lesson, real audio, frames, sync | Gate output including G2 as a failure, sync measurement |
| WP2c | `co-2` | Linear-equation claim kind and step role, recall answer forms | Full-verifier result on a linear chain |
| WP4 | `co-2` after A | planner.v4 with CO-2 rules, probes 9 to 13, size check, re-record changed fixtures only | Probe results, size check, fixtures re-recorded |
| WP5 | `co-2` | Scriptwriter, composer, end-to-end command | A generated lesson passing every gate |
| WP6 | `co-2` | Recall and reasoning question schema, analytics event schema, study design | Thresholds recorded |

Branches: `main` holds accepted work; `co-2` and `providers` are merged into `main` only after the owner accepts the stop report. Tag at each gate (`phase-0` exists; `co-2-wp2b` next).

## 8. Commands (the package files are the source of truth)

| Task | Command |
| --- | --- |
| All TypeScript tests | `pnpm exec vitest run` |
| Type check | `pnpm exec tsc --noEmit -p tsconfig.json` |
| Python verifier tests | in `services/verifier`: `PYTHONPATH=. python -m pytest -q tests` |
| Secrets scan | `pnpm secrets:check` |
| Gate and corruptions | `pnpm verify:gate` (and `pnpm verify:gate --list`) |
| Regenerate verifier inputs | `pnpm gen:ops` |
| Content | `pnpm content:seal`, `pnpm content:validate`, `pnpm content:seed` |
| Pattern report | `pnpm patterns:report` |
| Lesson quality report (ADR 0065; reports, never rejects) | `pnpm lesson:quality dist/lessons/<bundle id>` or `pnpm lesson:quality --reference` |
| Provider smoke and usage | `pnpm llm:smoke`, `pnpm llm:usage`, `pnpm llm:sizes` |
| Behaviour probes | `pnpm llm:probes` (1 to 8), `pnpm llm:probes --co2` (9 to 13) |
| Compile and play a lesson | `pnpm lesson:build <skillId>` (replay by default; `LLM_MODE=record` calls the model), then `pnpm lesson:play dist/lessons/<bundle id>` |
| Mutation testing | `pnpm mutate` (Stryker on the main configuration, then `scripts/mutation-floor.ts` for the per-file floor). Python step handlers: the Cosmic Ray commands in ADR 0047 |
| Docs check | `pnpm docs:check` |

`pnpm docs:check` runs with the test suite and fails if: a path in the section 1 table is missing (rows marked planned are skipped); an ADR file has no Status line; a frozen prompt's sha256 differs from `prompts/VERSIONS.md`.

## 10. Independence from YourTutor

- One repository, one Claude session working in its own folder. Both folders may be open together in a multi-root workspace to look at changes, but an editing session is started in one repository's own folder and never edits the other.
- No imports, no edited files, no shared `node_modules` and no symlinks across the two repositories. No relative path to the other repository in code, tests or scripts. The one allowed exception sits in YourTutor, not here: its copy script reads `../EduVideoEngine/dist/engine-package`.
- The only contact is the engine package plus `docs/ENGINE_INTERFACE.md`. A change to the contract is an ADR here, a version bump, and a matching ADR in YourTutor.
- Facts that must stay identical in both (the font files) are recorded in the contract as hashes. The engine keeps its own copies.
- Engine docs, prompts, change orders and ADRs never live in YourTutor, and YourTutor's docs never live here.
- Code, a test or a script that reads or builds a path into the other repository is a defect, including a path assembled from segments (for example `join("C", "Users", ...)`). The other project's name in a comment or in README prose is fine. Detect with `git grep -n -E "\.\./YourTutor|YourTutor[\\/]|\"YourTutor\"" -- . ":(exclude)docs"` and `git grep -n -E "\"Users\"" -- packages scripts`.
