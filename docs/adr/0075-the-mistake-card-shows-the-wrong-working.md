# ADR 0075: The mistake card shows the wrong working; the script for it is an authored stand-in

Status: proposed (agent, at the owner's request of 2026-10-22; the owner is asked to confirm, and to replace the stand-in with a recording when a model is chosen). Builds on ADR 0074.

## Decision
1. **The scene pass** `showWrongWorking` (`packages/pipeline/lesson/preview.ts`), over the finished scene of a mistake beat, like the hook and check passes (ADR 0072, 0073):
   - only for a `statement-card` whose beat has a grounded statement claim that names expressions (`exprRefs`, spec 2.3.0, ADR 0074), and only for the equations among them, at most two: nothing is shown that a person has not approved with the claim;
   - each equation is written on the card, under the note, as the sentence that says the claim begins, and dimmed (set aside) when it ends;
   - the scene is validated again and kept as it was if it fails; a claim that is not said, or a claim that names nothing, changes nothing; off in the baseline build (`features.motion`).
2. **The record edit, applied** (the owner approved it on 2026-10-22). `quad.sum.claim.mistake` declares `exprRefs: ["quad.wrong"]`, in the record and in the seed script (which would otherwise write the old record back); its hash is `82ceda1b…1de93`. No approval record exists in the repository (approvals are passed to a build by the caller, and the lesson is `publishable: no` for that reason), so there was nothing to redo; the new hash is what reopens any approval, and the owner's reading of the words (owner task 12) is still to do, for both grounded records.
3. **The script is an authored stand-in.** The record edit changes the scriptwriter's request (ADR 0074), and the model that recorded the old answer (`minimax/minimax-m3.1-flash:free`) was retired by its provider on 2026-10-22 (HTTP 404, "the free launch period ended"; one failed request is in the ledger). So no answer could be recorded. `pnpm llm:standin-script <answer.json>` writes an answer written by Claude Code as a fixture with `provenance: "authored-standin"` under the key of the request the scriptwriter now makes (ADR 0023 provides for this: it is for letting replay and the tests run, it is not a model output, every build that replays it says so, and recording over it replaces it). It sends nothing to any provider. The answer is the model's accepted answer of 2026-10-20 for every beat but the mistake beat, whose two sentences were written for this:
   - "Adding the numbers written in the equation gives {expr:quad.wrong}." and "But that total is not the sum of the roots." (the first uses the placeholder the claim now allows; a first draft that said "two numbers" was refused by G5(d) and changed);
   - the planner's recorded answer is replayed unchanged, because the planner's request does not read `exprRefs`.
   The stand-in is checked by the same rules a model's answer is (`checkScript`, the gates, the validator and the verifier): it passes without a repair.

## Consequences
- The generated lesson is spec 2.3.0, builds with 0 requests (3 replayed: the planner, repaired once as recorded, and the stand-in script), passes every gate and the SymPy verifier, and is `publishable: no` until the two grounded claims are approved.
- The mistake card now draws `5 + 6 = 11` as the first sentence begins and dims it as it ends, so the wrong working is on screen. The quality report still counts the beat as plain (a title, a line and an equation: no picture, nothing moved), and the `mistake-not-shown` finding is gone; the plain-beat count stays at 1 (the beat is words and one equation, by design).
- `recorded.test.ts` says what it replays: the planner is a recording, the script is a stand-in. Honest provenance matters: the lesson's words for the mistake beat were written by Claude Code, not generated by the pipeline's model.
- The free model's retirement is still the project's problem: every future recording needs a model the owner chooses (a paid one needs the owner's word, ADR 0060). A recording under a new model id also replaces the planner's key. When one is made it replaces this stand-in.
