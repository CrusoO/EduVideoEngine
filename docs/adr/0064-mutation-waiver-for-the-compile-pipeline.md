# ADR 0064: Mutation waiver for part of the compile pipeline (WP4 and WP5)

Status: proposed (agent; the owner is asked to accept). The waiver expires on 2026-11-30; `packages/gates/tests/waiver.test.ts` fails after that date.

## Context
`docs/ENGINE_WORKFLOW.md` section 5 rule 10 asks for a mutation score of 90 per file, in one full Stryker run, for every file in the main configuration; new code is in scope or covered by a dated waiver. WP4 and WP5 added 14 files under `packages/pipeline` (2,343 mutants). A first run over all 14 (2026-10-20) took longer than two hours to reach mutation testing and then died on an operating-system error reading a `package.json` under `node_modules` (the repository is in OneDrive), so the measurement was redone on the files whose tests are fast. 992 of the 2,343 mutants are static (module-level constants and patterns): each one needs the whole test suite, which Stryker estimated at 93 percent of the run time, so the measurement skips them (`ignoreStatic`).

## Evidence (2026-10-20 and 21, Stryker 8.7.1, perTest coverage, static mutants skipped)

## Decision
1. The six files that reach 90 join `stryker.config.json`. `vitest.stryker.config.ts` leaves out `build.test.ts` and `recorded.test.ts` (as it leaves out the size budget test, ADR 0024): they start the SymPy verifier and play a whole build, and the six files have unit tests of their own.
2. The four measured files below 90 and the four `build/*` files are waived until **2026-11-30** (`stryker.waived.config.json`: report-only, break 0, `_expires`, `ignoreStatic`). The waived config lists the four measured files; the `build/*` files are not in it because only the verifier-running tests cover them, and a run over them did not complete on this machine.
3. What survives in the four measured files is mostly the text of repair messages (the tests match a part of each message, not all of it) and boundary conditions of rules that are also enforced downstream by the gates, the validator or the verifier, so a surviving mutant there makes a repair message vaguer or a check redundant rather than letting a wrong lesson through. This is a reading of the survivor list, not a proof; the survivor lists are in `reports/mutation-waived-first.json` (not committed, regenerated by the command below).
4. Static mutants of the six main files are not measured by the run above. The next full `pnpm mutate` measures them; a file that falls below 90 there moves to the waiver by a new ADR.

## Consequences
- The pipeline's two model-facing passes (`arcplan`, `script/index`), the assembler and the claim builder are covered by many exact tests of their rules, but not at the 90 floor. Their gates (G1 to G7, the validator, the verifier) are in the floor.
- Reproduce: `node node_modules/@stryker-mutator/core/bin/stryker.js run stryker.waived.config.json` (about 30 to 60 minutes; run nothing else at the same time, the initial test run has a time limit).
- Before 2026-11-30: write exact-message tests for the four files, add the `build/*` files to a run on a machine where it completes, and move what reaches 90 to the main configuration; or renew by a new ADR with the owner's say.
